# Quality check 2026-11-01

The ten quality rules checked against the code, with evidence. Node.js 24.19.0, OpenJDK 21.0.12,
Windows 11. The casebook is a calculator over JSON files: it makes no network, database or
subprocess calls, so several rules apply only to its file reads and writes.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Every call can fail | fixed | The only external calls are file reads and writes. Found: `cli.js` `expected` swallowed every read error (`catch { have = '' }`), so a permission or I/O error looked like an out-of-date file and was overwritten; now only `ENOENT` counts as missing, anything else is reported. Found: a malformed case file crashed with a `SyntaxError` stack trace (JavaScript) or a `NullPointerException` (Java, missing fields); both now raise the repo's own error type (`CaseError`, `IllegalArgumentException`) naming the case, and the CLIs exit 2. |
| 2 | Writes safe to retry | fixed | Generated docs and `cases/expected/*.json` are derived from the case files, so running `npm run docs` twice gives the same files (the `--check` modes prove it in CI). Found: writes were in place, so an interrupted run could leave half a file; now `writeAtomic` in `docs.js` writes a temporary file and renames it. |
| 3 | No race conditions | N/A | Single-threaded command-line tools, no shared mutable state. |
| 4 | Don't trust the clock | N/A | No durations or timestamps. |
| 5 | Read before changing | pass | APIs used exist in the installed versions (`tsc --checkJs --strict` and javac `-Xlint:all -Werror` clean). No environment variables are read; `MVNLOCAL` in the Makefile is optional and documented there. Every path in the README exists. |
| 6 | Never break compatibility | pass | The case file format is unchanged; the new checks only refuse files that previously crashed. `--set` now refuses values it used to misread (empty value as 0, `a=1=2` as 1); valid uses are unchanged. |
| 7 | One source of truth | pass | `cases/*.json` is the source; `docs/cases/*.md` (generated sections) and `cases/expected/*.json` are rebuilt from it by `npm run docs` / `npm run expected`, and `make lint` fails if either is stale. Java recomputes from the same files and must match to 1e-12. Node 24 in `package.json` engines, CI and README; Java 21 in `pom.xml`, CI and README. |
| 8 | Small changes, no secrets, validate input | fixed | No secrets (grep for password/token/key: none). Found: `--set name=` became 0 and `--set a=1=2` became 1; `parseOverride` now accepts only a plain finite decimal. Found: case files were only checked for names, units and formulas; now `title`, `summary`, the lists and every derived entry's fields are checked in both languages. No new dependency. |
| 9 | Tests that can fail | fixed | No skipped or assertion-free tests (grep for `skip`, `todo`, `@Disabled`: none). Mutation table below: 17 of 20 killed before, 20 of 20 after. |
| 10 | Re-verify | pass | `tsc`: clean; docs and expected `--check`: up to date; `npm test`: 23 passed; `mvn verify`: 26 passed; `npm audit` and the OSV check run in CI. The CI result is recorded in the commit's workflow run. |
